## Risk-ranked findings

### P0

1. The shipping identity and update trust still belong to the historical application (`com.miruronative`, old signed fixtures and updater authority).
2. Legacy `UsagePing` networking and inherited provider credentials remain in the source.
3. No CI, branch protection, issue tracking or release environment exists.
4. The test baseline is red because signed update fixtures no longer represent the intended community authority.

### P1

1. The configuration cache is enabled but not serializable because of the parity-corpus task.
2. The default 6 GiB heap plus unconstrained worker count is unsafe on a 15 GiB developer host.
3. The build uses deprecated variant output APIs that must be migrated separately from the rebrand.
4. Native libraries are packaged with strip warnings; APK-level 16 KiB and ABI checks remain required.

## Baseline policy

The first implementation slice will preserve `minSdk 22`, the `com.anilili` source namespace, both product flavours, backup format compatibility and local diagnostics. It will not publish a release or enable remote telemetry. The owner explicitly authorised creation of new local signing identities and protected GitHub release-environment secrets on 2026-11-03.
